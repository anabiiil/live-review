# LiveReview v2 — Redesign + comment workflow — Implementation Plan

> For agentic workers: executed with superpowers:subagent-driven-development. Spec: `docs/superpowers/specs/2026-11-10-redesign-and-comment-workflow.md` (binding). Earlier spec/plan (v1) still bind everything not changed here.

**Goal:** modern UI with margin comment marks, a comments page, notification center, and resolve notifications both ways (in-app, desktop, email).

**Global constraints (unchanged from v1 unless noted):** Node ≥24 ESM JSDoc; no new runtime deps except the three `@fontsource/*` font packages; no inline scripts (CSP), no untrusted strings in HTML sinks (`h()`/textContent only); hidden files never leak (snippets come from anchors and must be `null` for hidden/wiped threads); `npm test` pristine; each task ends with a commit whose message ends with the implementer's own Co-Authored-By trailer; all git stays read-only.

## Task 1 — Notifications + threads listing (backend)
Files: `src/db.js` (migration v2), `src/notify/notifier.js` (new; replaces `src/notify/ownerMailer.js`, delete it and its tests, port its tests), `src/notify/notificationStore.js` (new), `src/http/ws.js` (sendToEmail / owner targeting), `src/http/api.js`, `src/http/adminApi.js`, `src/app.js`, `src/comments/store.js` (threads listing helper, participants), `src/config.js` (`ownerEmailNotifications` default true), tests under `test/notify/`, `test/http/`.
- Migration v2: `CREATE TABLE notifications(id INTEGER PRIMARY KEY, recipient_email TEXT NOT NULL, project_id INTEGER NOT NULL REFERENCES projects(id) ON DELETE CASCADE, comment_id INTEGER REFERENCES comments(id) ON DELETE CASCADE, kind TEXT NOT NULL CHECK(kind IN ('comment','reply','resolved','reopened')), actor_email TEXT NOT NULL, created_at INTEGER NOT NULL, read_at INTEGER)`, index `(recipient_email, created_at DESC)`; `ALTER TABLE users ADD COLUMN email_notifications INTEGER NOT NULL DEFAULT 1`.
- Recipient rules, event mapping (`comment-changed` kinds create→comment, reply→reply, resolve with resolved=true→resolved, resolve with resolved=false→reopened; edit/delete → nothing) exactly as the spec. The `comment-changed` event must carry `resolved` for resolve events and the actor email (add to emitters in api.js). Owner email = normalized `config.ownerEmail`; a reviewer recipient must still be a member.
- Live delivery: `{type:'notification', notification:{id, kind, projectSlug, projectName, commentId, threadId, path, line, target, actorName, excerpt, url, createdAt, read:false}}` to recipient sockets; keep sending the v1 `notify` message to owner sockets for create/reply until Task 4 switches the client, then Task 4 removes it.
- Email: batched per recipient, `delayMs` default 60000 (createApp option `notifyDelayMs`); subjects: single → `"{actor} replied on {project}"`, `"{actor} commented on {project}"`, `"{actor} marked your comment resolved in {project}"`, `"{actor} reopened a comment in {project}"`; several → `"{n} updates on {project|LiveReview}"`. Body per item: what happened, `path:line`, excerpt (≤500 chars), link (owner localhost admin port; reviewer `https://{publicHost}`). Skip when email unconfigured or the recipient's preference is off.
- APIs per spec: notifications list/read, prefs (reviewer → users.email_notifications; owner → config.ownerEmailNotifications via saveConfig), `GET /api/p/:slug/threads`, `GET /api/admin/threads`. `/api/me` gains `emailNotifications`.
- Snippet: from anchor `{before, lineText, after}` → `[{no, text, focus}]` numbered around `line`; `null` when `hidden` or anchor null.
- Tests: recipient matrix (owner resolves reviewer thread → reviewer notified, not owner; reviewer resolves → owner notified; reply notifies other participants + owner; removed member not notified; actor never notified), persistence + read marking, WS delivery to the right sockets only, email batching per recipient + preference off, threads listing filters/snippets/hidden null, access control (no-access 404 identical).
